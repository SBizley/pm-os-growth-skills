# Story Mapping for Delivery Inception

*Decide · 3-4 hrs · Ready to decide*

# 🎯 **Purpose**

Transform validated solutions into a **shared delivery blueprint**.

Story mapping connects **customer journeys**, **business goals**, and **team workstreams** - so everyone agrees on **what we’re building, why, and what “done” looks like.**

> *“Story mapping turns a long list of requirements into a narrative everyone understands.” - Jeff Patton*
> 

### 🧩 **When to Use**

- After **Solution Validation** (we know it’s worth building).
- Before delivery planning or epic creation.
- When teams need **alignment** on MVP scope, sequencing, or dependencies.

### ⚙️ **How to Run**

**Duration:** 3–4 hours (cross-functional session)

**Facilitator:** Product Manager / Designer

**Participants:** PM, Eng, Design, Data, Commercial, Ops

### **1️⃣ Define the goal & user**

Start with clarity:

- What’s the **user problem** we’re solving?
- What’s the **business goal / success metric** (e.g., ARR uplift, conversion rate, retention)?
- Which **persona or archetype** does this apply to?

✅ *Output:* 1-line user goal + 1-line success metric.

### **2️⃣ Map the high-level user journey**

Lay out the **end-to-end steps** the user takes to reach the goal.

Use real customer language, not internal terms.

**Example: “Apply for Funding” journey**

1. Discover funding
2. Start application
3. Submit details
4. Approval & payout
5. Repayment tracking

✅ *Output:* The “backbone” of the story map - the horizontal axis.

### **3️⃣ Break down actions under each step**

For each step, brainstorm what users do (and what systems or teams enable it).

Add **sticky notes vertically** under each stage.

**Example:**

- Start application → Enter business details → Connect bank → Verify ID
- Submit details → Review summary → Confirm application

✅ *Output:* Full vertical story map of actions per stage.

### **4️⃣ Identify pain points & dependencies**

Overlay insights from validation (user quotes, analytics, ops blockers).

Mark with ⚠️ or 🔗 to show where discovery findings highlight complexity.

✅ *Output:* Risks and cross-team dependencies made visible early.

### **5️⃣ Slice the MVP**

Draw a horizontal line across the map and agree **what’s in the first release**.

Use these filters:

- 🎯 Does it deliver *end-to-end value* for the user?
- 💰 Does it support our success metric?
- 🧩 Can we build it without waiting on major dependencies?

✅ *Output:* “Thin-slice” MVP scope, written as epics or stories.

*(Example: Apply → Verify → Approve manually → Notify → Fund)*

### **6️⃣ Define success & telemetry**

For each slice, define **success metrics and instrumentation.**

**Example:**

| Stage | Metric | Target |
| --- | --- | --- |
| Start application | % of visitors who start | +20% vs baseline |
| Submit details | Completion rate | ≥80% |
| Approval & payout | Avg. time to fund | <24h |
| Retention | % repeat borrowers | +15% |

✅ *Output:* MVP metric dashboard plan.

### **7️⃣ Agree next steps & owners**

Convert MVP slices → backlog epics in Jira/Linear.

Assign clear owners per vertical (PM, Design, Eng).

Schedule the **Delivery Inception playback** to align wider teams.

✅ *Output:* Aligned roadmap and playback deck.

### 📊 **Workshop Template**

| Step | Description | Outputs | Owner | Status |
| --- | --- | --- | --- | --- |
| Goal & Persona | Clarify user + metric | User + metric | PM | ✅ |
| Journey Backbone | 5–7 top-level steps | Horizontal map | UX | ✅ |
| Actions / Tasks | Detailed vertical slices | Map of all actions | PM/UX/Eng | 🔄 |
| Pain Points | Add from validation | Risk markers | Ops/Data | 🔄 |
| MVP Slice | Define thin slice | MVP line + epic list | PM/Eng | 🟢 |
| Success Metrics | Define telemetry | Metric sheet | Data | 🟢 |
| Playback | Summarise and align | One-pager / deck | PM | 🟢 |

### 🧠 **Tips**

- Focus on **story flow**, not backlog grooming.
- Keep slices small - **ship learning, not volume.**
- Revisit story maps after every major iteration or market change.
- Use **colour-coding** (e.g. 💚 built, 🟡 next, 🔴 risk).
- Keep photos or digital copies in Notion to maintain a versioned record.

### 🧾 **Example Outputs (Funding Funnel MVP)**

- **Goal:** Reduce drop-off in funding applications by 30%.
- **Persona:** Existing customer, Medium SME, needs short-term cashflow.
- **Journey Backbone:** Discover → Apply → Submit → Approve → Payout.
- **MVP Slice:** Manual underwriting flow with instant eligibility & email notifications.
- **Metric:** Submission rate +30%, time-to-fund <24h.
