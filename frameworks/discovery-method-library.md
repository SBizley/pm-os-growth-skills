# Discovery method library

The workshop and research methods I reach for, picked by what you're
trying to learn. Pairs with the Discovery skill: use that to scope the
opportunity and find the riskiest assumption, then come here to pick
the session to run. Full guides are in `method-guides/`.

I've deliberately kept this to 14. A library of 50 looks thorough, but
in practice I use the same dozen or so, and a founding PM needs to know
which three to run on Monday, not browse a catalogue.

## Pick by what you need

| I need to... | Use this | Time |
|---|---|---|
| Make sense of a round of customer interviews | Customer Interview Synthesis | 1-2 hrs |
| See the whole customer experience, including where it hurts | Journey Map | 1-2 hrs |
| Turn a problem into a question people can generate ideas against | How Might We | 1 hr |
| Turn an assumption into something testable | Hypothesis Statement | 30 min |
| Find the assumption that would kill this if it's wrong | Assumption Map | 45 min |
| Get past the first obvious idea, fast | **Crazy 8s** | 45 min |
| Make an idea concrete enough to react to | Storyboard | 1-2 hrs |
| Agree what we offer, to whom, and test the words | **Value Proposition Exercise** | 90 min + testing |
| Check demand before building anything | Fake Door Test | 2 hrs to set up |
| Agree what v1 actually is | **Story Mapping** | 2-3 hrs |
| Sort a long list into now and later | Impact / Effort Map | 30 min |
| Set goals a team can measure | OKRs | 1 hr |
| Kick off a new project properly | Project Kick-Off (recipe) | 4 hrs |
| Get a new team working together | Team Time (recipe) | 3-4 hrs |

## A typical discovery run with these

How Might We → Crazy 8s → Assumption Map → Fake Door Test or Value
Proposition Exercise → Story Mapping. That gets you from a fuzzy problem
to a scoped v1 in about two weeks of elapsed time.

## How to run any of them

1. Write down the one question the session has to answer before you book it
2. Set the purpose, timings and output at the start of the session
3. Capture the output where the team will see it again (`context/` if
   it changes what's true about the product)
4. Carry it into the next step. A workshop output that sits in a Miro
   board nobody opens was a nice afternoon, not discovery.
